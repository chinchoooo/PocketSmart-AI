# Communication

## Communication Plan

| S.No | Communication Type | Frequency | Channel / Tool | Participants | Purpose |
|---|---|---|---|---|---|
| 1 | Team Standup | Daily | WhatsApp group (5-minute text update) | All 5 members | Share progress and blockers |
| 2 | Progress Update | Weekly | Google Meet | All members | Review sprint board and merge status |
| 3 | Issue / Bug Discussion | As Needed | GitHub Issues and WhatsApp | Developer and QA (Rangesh V S) | Track and fix defects |
| 4 | Stakeholder Review | Bi-Weekly | In-person / Meet with faculty mentor | Team lead and mentor | Feedback on scope and quality |
| 5 | Final Demo Rehearsal | Once | Lab or Google Meet | All members | Time the demo and assign roles |
| 6 | Code Review | Per pull request | GitHub | Author and one reviewer | Keep quality high |

### Communication Challenges & Resolutions

| S.No | Challenge Faced | Resolution / Action Taken |
|---|---|---|
| 1 | Merge conflicts when several members edited the same files | Short-lived feature branches, one owner per module, pull-request review |
| 2 | Gemini model names in the brief were outdated | Model made configurable with automatic fallback; decision shared in the group |
| 3 | Members had different local setups | Pinned `requirements.txt`, `.env.example` and a Dockerfile |
